# ConnectWise Automate Alerts

## Overview

Alerts in ConnectWise Automate are notifications generated by monitors, scripts or system events. Through Conduit they are **read-only**: the Automate REST API exposes only `GET /Alerts`, `GET /Alerts/{id}` and `GET /Computers/{id}/Alerts`, with no status field and no acknowledge, resolve or close route. The acknowledge tool was removed in connectwise-automate-mcp 2.0.0 for that reason. Acknowledging or clearing an alert is done in the Automate console, or the follow-up is tracked as a PSA ticket.

## Anti-triggers

- **The rule that produced the alert** — thresholds, templates and
  assignment are monitor configuration; use
  `connectwise-automate-monitors`.
- **The PSA ticket raised from an alert** — the ticket's board, status,
  priority and SLA clock live in ConnectWise PSA. Use
  `connectwise-psa-tickets`.
- **Another RMM's alerts** — Datto RMM, NinjaOne, Atera and Auvik all use
  the word; use `datto-rmm-alerts`, `ninjaone-alerts`,
  `atera-alerts` or `auvik-alerts`.

## Tools

| Tool | Tier | Arguments | Purpose |
|------|------|-----------|---------|
| `cwautomate_alerts_list` | read | `computer_id`, `client_id`, `severity` (matches the alert's `Severity.Id`), `limit` (default 50), `skip` | List alerts, optionally filtered |
| `cwautomate_alerts_get` | read | `alert_id` (required) | One alert's full detail |

Filtering is done by the server through Automate's `condition` expression; Automate silently ignores any other query parameter, so do not expect free-form filters to narrow the result.

## Key Concepts

### Alert sources

| Source | Example |
|--------|---------|
| Monitor | CPU > 90% |
| Script | Backup script reported failure |
| Event Log | Security event trigger |
| System | Agent offline |

### Severity levels

| Level | Value | Response |
|-------|-------|----------|
| Information | 1 | Review at convenience |
| Warning | 2 | Investigate within hours |
| Error | 3 | Respond within SLA |
| Critical | 4 | Immediate response |

There is no alert status in the API. "Open" versus "handled" is not visible from these tools; an alert that is still returned is still present in Automate.

See [references/fields.md](references/fields.md) for the alert fields and [references/api.md](references/api.md) for the underlying REST routes.

## Workflows

### Critical alerts dashboard

1. `cwautomate_alerts_list` with `severity: 4`, then `severity: 3`, paging with `limit`/`skip` until a page returns fewer than `limit` rows.
2. Group by client (`client_id` on each alert) and by computer.
3. For the top computers, `cwautomate_computers_get` to show online state and last contact.

### Triage one client

1. `cwautomate_clients_list` (or `cwautomate_clients_get`) to resolve the client ID.
2. `cwautomate_alerts_list` with `client_id`.
3. Collapse repeats from the same monitor on the same computer into one finding, and note the oldest occurrence.

### Raise follow-up work

Automate alerts cannot be acknowledged from here, so the durable record is a PSA ticket. Draft the ticket (client, computer, alert subject, first-seen time, severity) and create it with the PSA plugin's tools (for ConnectWise PSA, `cw_create_ticket`), after the operator confirms.

### Script-generated alerts

When an alert comes from a script, read the script's recent results with `cwautomate_scripts_history` for that computer before proposing a re-run.

## Error Handling

| Error | Status | Cause | Resolution |
|-------|--------|-------|------------|
| Alert not found | 404 | Invalid alert ID, or the alert was cleared | Re-list alerts |
| Permission denied | 403 | API user cannot see that client | Check the Automate user's client permissions |
| Unknown tool | — | Calling the removed acknowledge tool | Alerts are read-only; handle the follow-up in the PSA or the Automate console |

See [references/examples.md](references/examples.md) for worked triage examples.

## Best Practices

1. Filter by severity first, then by client.
2. Collapse duplicate alerts before reporting counts.
3. Track follow-up in the PSA, not in Automate.
4. Review recurring alerts against their monitor configuration.
